## Pipeline functions

### `createExtractor(config)`

Create a source-tree extraction pipeline. For PDF inputs, callers must provide preprocessed `SourceSpan[]` through `ExtractOptions.sourceSpans`. For Docling inputs, CL SDK derives spans from the serialized Docling document. If extraction receives no spans, it throws:

```text
cl-sdk extraction now requires preprocessed source spans. Run LiteParse or another source-span preprocessor and pass ExtractOptions.sourceSpans; legacy raw-PDF page-map extraction has been removed.
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `config` | `ExtractorConfig` | Pipeline configuration |

**Returns:** `{ extract(input: ExtractionInput, documentId?: string, options?: ExtractOptions): Promise<ExtractionResult> }`

```typescript
import { buildPageSourceSpans, createExtractor } from "@claritylabs/cl-sdk";

const extractor = createExtractor({
  generateObject: myGenerateObject,
  onProgress: (msg) => console.log(msg),
  onTokenUsage: (usage) => console.log(`Tokens: ${usage.inputTokens} in, ${usage.outputTokens} out`),
});

const sourceSpans = buildPageSourceSpans([
  { documentId: "policy-123", sourceKind: "policy_pdf", pageNumber: 1, text: pageOneText },
]);

const result = await extractor.extract(pdfBase64, "policy-123", { sourceSpans });
```

`ExtractionInput` is either a `PdfInput` value (`string`, `URL`, `Uint8Array`, or `{ fileId }`) plus `ExtractOptions.sourceSpans`, or a Docling input:

```typescript
const result = await extractor.extract({
  kind: "docling_document",
  document: doclingDocumentJson,
  sourceKind: "policy_pdf",
}, "policy-123");
```

Docling conversion is host-owned. CL SDK consumes serialized `DoclingDocument` JSON, normalizes page text and provenance into source spans, and then runs the same source-tree extraction path.

The current extraction path is:

1. **Normalize source spans** -- merge Docling-derived spans and caller-provided spans, normalize text, remove duplicate or unusable spans, and derive `sourceChunks`.
2. **Persist source evidence** -- when `sourceStore` is configured, save source spans and chunks before extraction.
3. **Build the source tree** -- deterministically construct document, page group, page, form, endorsement, section, schedule, clause, table, row, cell, and text nodes from existing spans.
4. **Apply semantic grouping** -- group declarations, policy forms, endorsements, sections, and schedules from parser titles and source text. The grouping code may relabel or regroup existing source nodes; it does not invent source text, source span IDs, pages, or bounding boxes.
5. **Extract the operational profile** -- call `generateObject` with a bounded source-evidence packet for product-critical facts such as policy number, named insured, insurer, broker, policy period, coverage units, limits, deductibles, premiums, and endorsement support.
6. **Validate and merge citations** -- reject uncited facts and source IDs that are not present in the current source tree/spans.
7. **Clean up coverages** -- when coverage units exist, run one bounded source-backed cleanup pass that keeps, drops, or updates existing coverage rows by `coverageIndex`.
8. **Project compatibility output** -- materialize `document`, `documentMetadata`, and `documentOutline` as views over `sourceTree` and `operationalProfile`; return `chunks: []` on this v3 path.

<Callout type="info">
  The `extract` method accepts an optional `documentId`. If omitted, a timestamped ID is generated automatically.
</Callout>

### `chunkDocument(doc)`

Convert an `InsuranceDocument` into `DocumentChunk[]`. This remains available for legacy or manually assembled documents, but source-tree extraction returns `chunks: []` because broad structured chunks are no longer the primary evidence corpus.

```typescript
import { chunkDocument } from "@claritylabs/cl-sdk";

const chunks = chunkDocument(document);
await memoryStore.addChunks(chunks);
```

For newly extracted v3 documents, index `result.sourceTree` for retrieval and keep `result.sourceSpans` for exact highlights.

## Configuration types

### `ExtractorConfig`

```typescript
interface ExtractorConfig {
  /** Provider callback for structured output with Zod schemas */
  generateObject: GenerateObject;
  /** Called after each model call with token counts, when the provider reports usage */
  onTokenUsage?: (usage: TokenUsage) => void;
  /** Called with human-readable progress messages during extraction */
  onProgress?: (message: string) => void;
  /** Optional async logger */
  log?: LogFn;
  /** Pass-through provider options forwarded to extraction model calls */
  providerOptions?: Record<string, unknown>;
  /** Optional source evidence persistence */
  sourceStore?: SourceStore;
  /** Optional quality gate behavior */
  qualityGate?: "off" | "warn" | "strict";
  /** Optional model metadata for resolving default task budgets */
  modelCapabilities?: ModelCapabilities;
  /** Optional model metadata by task kind for routed hosts */
  modelCapabilitiesByTaskKind?: Partial<Record<ModelTaskKind, ModelCapabilities>>;
  /** Optional per-task budget constraints */
  modelBudgetConstraints?: Partial<Record<ModelTaskKind, ModelBudgetConstraint>>;
}
```

`generateText`, `convertPdfToImages`, page-map concurrency, focused extractor concurrency, review mode, and checkpoint options are not part of the current extraction config. They may still exist in other SDK workflows or older release notes, but they are not used by `createExtractor()` in the published 3.2.13 API.

### `ExtractionInput`

```typescript
type ExtractionInput =
  | PdfInput
  | {
      kind: "docling_document";
      document: DoclingDocumentLike;
      sourceKind?: SourceKind;
    };
```

`PdfInput` still identifies the source document for compatibility, but policy extraction does not send raw PDF bytes or page images as the primary extraction context. Pass source spans produced by LiteParse, Docling, PDF.js, OCR, or another parser.

### `ExtractOptions`

```typescript
interface ExtractOptions {
  /** Caller-provided raw source spans for this document. */
  sourceSpans?: SourceSpan[];
}
```

For PDF inputs, `sourceSpans` are required. For Docling inputs, they are optional and are merged with the spans derived from the Docling document.

### `ExtractionResult`

```typescript
interface ExtractionResult {
  /** Compatibility policy or quote projection */
  document: InsuranceDocument;
  /** Empty on v3 source-tree extraction paths */
  chunks: DocumentChunk[];
  /** Source spans used for grounding */
  sourceSpans: SourceSpan[];
  /** Source chunks derived from sourceSpans */
  sourceChunks: SourceChunk[];
  /** Canonical source hierarchy */
  sourceTree?: DocumentSourceNode[];
  /** Source-backed product fact projection */
  operationalProfile?: PolicyOperationalProfile;
  /** Non-blocking extraction warnings */
  warnings?: string[];
  /** Aggregate token usage across model calls that reported usage */
  tokenUsage: TokenUsage;
  /** Whether provider callbacks returned usage for each model call */
  usageReporting: {
    modelCalls: number;
    callsWithUsage: number;
    callsMissingUsage: number;
  };
  /** Timing and model-call performance summary */
  performanceReport: PerformanceReport;
  /** Source-tree warning and artifact report */
  reviewReport: ExtractionReviewReport;
}
```

`ExtractionResult.document` is a compatibility projection. Product surfaces that need source truth should prefer `sourceTree` for wording/hierarchy and `operationalProfile` for product-critical facts.

### `PolicyOperationalProfile`

The operational profile is the bounded source-backed fact layer:

```typescript
interface PolicyOperationalProfile {
  documentType: "policy" | "quote";
  linesOfBusiness: AcordLobCode[];
  policyNumber?: SourceBackedValue;
  namedInsured?: SourceBackedValue;
  insurer?: SourceBackedValue;
  broker?: SourceBackedValue;
  effectiveDate?: SourceBackedValue;
  expirationDate?: SourceBackedValue;
  retroactiveDate?: SourceBackedValue;
  premium?: SourceBackedValue;
  operationsDescription?: SourceBackedValue;
  declarationFacts: OperationalDeclarationFact[];
  coverages: OperationalCoverageLine[];
  parties: OperationalParty[];
  endorsementSupport: OperationalEndorsementSupport[];
  sourceNodeIds: string[];
  sourceSpanIds: string[];
  warnings: string[];
}
```

`linesOfBusiness` is the single top-level policy classification field. Values are ACORD line of business codes. Serialized legacy `policyTypes` blobs are accepted at parse time and normalized to `linesOfBusiness`.

`declarationFacts` is the source-backed declaration fact stream for host persistence. It carries named-insured identity details such as mailing address, DBA, entity type, tax ID, additional named insured rows, and other key declarations with normalized values plus source IDs.

`parties` keeps policy-scoped named-insured, producer/broker, insurer/carrier, and MGA/administrator identities. Each party may carry a partial or complete `OperationalAddress`; the compatibility document projection materializes only complete named-insured, producer, and insurer addresses. `operationsDescription` is the insured's directly source-backed business or operations description rather than an inference from coverages or external research.

## Schema utilities

### `toStrictSchema(schema)`

Transform a Zod schema for strict structured output compatibility. Recursively converts `.optional()` properties to `.nullable()` so all properties appear in the JSON Schema `required` array.

```typescript
import { toStrictSchema } from "@claritylabs/cl-sdk";

const strict = toStrictSchema(z.object({
  name: z.string(),
  age: z.number().optional(),
}));
```

<Callout type="info">
  You do not need to call this yourself for `createExtractor()`; the pipeline applies it automatically before every `generateObject` call.
</Callout>

### `safeGenerateObject(generateObject, params, options?)`

Wraps a `generateObject` call with schema strictification, retry on transient errors, and optional fallback values.

```typescript
import { safeGenerateObject } from "@claritylabs/cl-sdk";

const { object } = await safeGenerateObject(
  myGenerateObject,
  { prompt: "...", schema: MySchema, maxTokens: 1024 },
  {
    fallback: { status: "unknown" },
    maxRetries: 2,
  },
);
```
