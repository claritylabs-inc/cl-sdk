In CL SDK 4.0, policy classification is part of the source-backed operational profile, not a separate raw-PDF classifier phase. The operational-profile model receives bounded source evidence from the source tree and returns `linesOfBusiness` alongside the rest of the product-critical facts.

<Callout type="info">
`linesOfBusiness` is the single top-level policy classification field. Values are ACORD line of business codes. Do not add a parallel `policyTypes`, `coverageTypes`, or deterministic coverage-origin projection in consumers.
</Callout>

## Operational Profile Field

```typescript
interface PolicyOperationalProfile {
  documentType: "policy" | "quote";
  linesOfBusiness: AcordLobCode[];
  // policy number, parties, dates, premium, coverages, endorsements...
}
```

`linesOfBusiness` contains all detected ACORD codes, for example:

```typescript
["CGL", "AUTOB"]
```

The parser accepts serialized legacy profile blobs with `policyTypes` and normalizes them to `linesOfBusiness` when parsed. New extraction output emits `linesOfBusiness`.

## How It Is Inferred

Classification is source-backed. The profile merge layer resolves `linesOfBusiness` from:

- source-backed coverage names and declaration evidence
- explicit ACORD code values returned by the operational-profile model
- legacy policy-type hints when parsing cached blobs
- a default of `["UN"]` when the source evidence does not support a more specific code

The SDK does not run the removed full-PDF classify/page-map/template flow in the current extraction path.

## Supported Mappings

The SDK exports `AcordLobCode`, `AcordLobCodeSchema`, `ACORD_LOB_CODES`, `ACORD_LOB_LABELS`, `LEGACY_POLICY_TYPE_TO_LOB`, `PERSONAL_LOB_CODES`, `normalizeOperationalLinesOfBusiness`, and `resolveOperationalProfileLinesOfBusiness`.

Key legacy mappings:

| Legacy value | ACORD output |
| --- | --- |
| `general_liability` | `CGL` |
| `commercial_property` | `PROPC` |
| `commercial_auto`, `non_owned_auto` | `AUTOB` |
| `workers_comp` | `WORK` |
| `umbrella` | `UMBRC` |
| `excess_liability` | `EXLIA` |
| `professional_liability` | `EO` |
| `cyber`, `environmental`, `product_liability` | `OLIB` |
| `management_liability_package` | `DO`, `EPLI`, `FIDUC` |
| `homeowners_ho3`, `homeowners_ho5`, `renters_ho4`, `condo_ho6` | `HOME` |
| `flood_nfip`, `flood_private` | `FLOOD` |
| `life`, `long_term_care`, `pet`, `travel`, `identity_theft`, `title`, `other` | `UN` |

The unknown/unsupported ACORD codes `ACHE`, `INTER`, `LICPT`, `LSTIN`, `NWFGR`, `PAPER`, `SCAP`, and `SFRNC` are not part of the accepted schema. `CRIM` is normalized to `CRIME`.

## Multi-Line Documents

Many package policies cover multiple lines of business. `linesOfBusiness` can contain more than one code, and `operationalProfile.coverages` should preserve each source-backed coverage unit rather than forcing the document into a single line-specific template.
